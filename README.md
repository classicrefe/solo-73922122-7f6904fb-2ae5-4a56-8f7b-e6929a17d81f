# 涂料灌装 · 换配方重贴标签核对

Flask + SQLite 的核对页。导入一班的留样复核 CSV，按瓶号算出换配方后哪些瓶子
的标签必须重贴、哪些只在部分候选切点下才会错标，以及错标瓶数的精确上下界。
网页可对单瓶留样补改判定、更正“最后一瓶旧标签”编号，并实时对比重贴范围。

## 模型

- 瓶号 `1..N` 按灌装顺序连续排列，`N ≤ 100000`。
- 配方只换一次，切点 `R` = **最后一瓶旧配方**；标签只换一次，切点 `L` = **最后一瓶旧标签**。
  两个切点都落在相邻瓶之间（`R, L ∈ [0, N]`，其中 0 表示整批都是新配方/新标签）。
- 留样判定：`old`（旧配方）、`new`（新配方）、`pending`（待核，不产生约束）。
- 对配方切点 `R` 的冲突数为

  `f(R) = #{旧留样 瓶号 > R} + #{新留样 瓶号 ≤ R}`

  取 **`argmin f`** 作为所有可能的配方切点（“与已核留样冲突最少”）。
- 配方切点 `R` 与标签切点 `L` 不一致时，错标瓶号恰好是 `(min(L,R), max(L,R)]`。
  因此：
  - **必错号段** = 所有 `argmin` 切点错标集合的交 = `(max C, L]` 或 `(L, min C]`；
  - **仅在部分切点下错标** = 并集减交集 = `(min C, max C]`；
  - **错标瓶数精确上下界**：
    `min |L−R|`、`max |L−R|`（R 取遍 `argmin` 切点），都可精确给出；
  - 只有两个号段、永远连续，不需要枚举 10 万个瓶号即可输出。

`argmin` 可能不连续（例如留样本身互相矛盾时），页面会标注“不连续”。

## 数据与复杂度

SQLite 保存两类数据：

1. `samples` 表：留样瓶号 + 判定；
2. `meta.label_cut`：录入的最后一瓶旧标签编号。
   （同时存 `meta` 里的版本号/计数/时间戳。）

冲突函数 `f(0..N)` 的**懒标记最小值线段树持久化在 `seg` 表中**（每个节点一行：
最小值、最小值个数、懒标记）。因此冷启动/多 worker 下查询也不重放留样：

- 单瓶补改：删旧判定 + 加新判定，各一次区间加 ⇒ 触及 `O(log N)` 个节点，
  同时在事务内更新 `samples` 一行与 `meta` 计数，`query_nodes` 可在页面/API 中看到
  （10 万瓶实测 21–25 个节点）。
- 出数：根节点取全局最小值与个数，再按窗口找 `argmin` 的首/末/前驱/后继
  ⇒ `O(log N)` 次节点读取（10 万瓶实测 87–95 个节点）。
- 一次导入：`O(N + 留样数)` 重建整棵树（允许的批量操作）。

同一已提交状态：读接口在一个 `BEGIN` 快照里读完 `meta` + 树；写接口在一个
`BEGIN IMMEDIATE` 里同时改树、留样、计数与版本号，并在**同一事务内**顺手算出该笔
写入紧邻的「补改前 / 补改后」两份核对快照（各只读 O(log N) 个树节点）随回执返回。
写失败整体回滚，接口返回 500，页面沿用原已提交结果（失败响应里也带回服务端最新
已提交快照）。

### 补改前后对比（多窗口交错规则）

每笔补判留样或换标号更正都按**该笔自身紧邻的前后核对结果**比较，互不串台：

- 写接口在同一事务里返回 `before`/`after` 两份快照与本笔 `req_id`（页面提交时
  生成、服务端原样回显）。因此 A 窗口更正换标号、B 窗口随后补判留样时，B 的
  「补改前」已经包含 A 的换标号但「补改后」只反映 B 自己的判定变化；对比中只
  高亮本笔真正改变的行，别人的改动不会被算进本笔。
- **首次补录换标号**时，该笔 `before` 快照为 `label_missing`，页面前一栏整体
  显示「未录入」并附说明。
- 提交按钮在等待回执期间保持可用，可连续发起多笔补改；页面为每笔登记本地
  递增 `order`。对比面板展示**本页最近发起且已收到成功回执**的那一笔（更早
  发起的迟到回执不会顶掉更新的对比）；主核对区严格按实际提交先后（版本号）
  更新，迟到的旧回执不会把页面回滚。
- `meta.epoch` 是班次纪元：导入、清空、载入演示都会铸造新的随机纪元。清空
  重导后若收到旧班次的迟到成功回执，只要它仍是本页最近发起的成功补改，仍
  展示该笔自身的前后差异并打上「旧班次回执」徽标，但当前核对继续显示新班次。
- 写入失败的回执不进入对比列表；失败携带的已提交快照仅在同纪元且不旧于当前
  页面时才采纳，保证已提交核对结果不被覆盖。
- 单瓶补改仍只触及 O(log N) 个树节点；事务内两份快照各读 O(log N) 个节点，
  10 万瓶实测写全程 < 5 ms，最坏时间复杂度保持次线性。

## 运行

```bash
docker compose up --build      # 打开 http://localhost:8000
```

数据卷 `relabel-data` 挂到容器 `/data/relabel.sqlite3`。

不打容器时：

```bash
pip install -r requirements.txt
RELABEL_DB=/tmp/relabel.sqlite3 python -m app     # 或 gunicorn 'app:create_app()'
```

测试：

```bash
python -m pytest -q          # 后端：算法 / 持久化 / HTTP / 并发 / 规模 / 交错
node --test tests/js/diff.test.js   # 前端对比与班次归位纯逻辑
```

## 网页流程

1. **导入**：填总瓶数、最后一瓶旧标签编号（可留空后补），选 CSV（`bottle,verdict`；
   表头可写 `瓶号,判定`，判定接受 `old/new/pending`、`旧/新/待核`、`O/N/P` 等；
   支持 UTF-8 与 GB18030）。整份 CSV 校验通过才提交，重复瓶号/未知判定/越界瓶号
   会整份拒绝。
2. **核对结果**：最少冲突数、并列切点个数与范围、必错号段、仅部分切点错标号段、
   错标瓶数上下界与可视化条。
3. **补改**：输入瓶号 + 新判定（或更正换标号），提交后立即显示该笔自己的
   “补改前 → 补改后”对比，只高亮本笔改变的项目；等待回执期间仍可继续补改，
   交错到达的回执按发起次序与班次纪元分别归位。
4. **演示**：`载入演示数据` 直接写入 10 万瓶的确定性场景：换标号 #58720，
   真值切点 #58400，#58581 与 #58800 为待核留样。初始时 488 个切点并列最优、
   没有必错瓶；把 #58800 补改为“旧配方”后必错号段变为 #58721–#58800（80 瓶），
   仅部分切点错标 #58801–#58887（87 瓶），上下界变为 80–167 瓶。
   改回“待核”即恢复原状。

`sample_data/shift-a-review.csv` 是同一演示数据，可直接上传。

## 目录

- `app/algorithm.py`：冲突函数、区间加/最小值计数线段树、切点区间推导与暴力对照实现
- `app/store.py`：SQLite 事务、持久化线段树、单瓶增量更新、损坏自愈重建
- `app/csvio.py`：CSV 解析/别名/编码处理
- `app/__init__.py`：Flask 路由（`/api/import`、`/api/summary`、`/api/sample`、
  `/api/label`、`/api/demo`、`/api/reset`、`/healthz`），写接口回显 `req_id` 并
  返回同事务的 `before`/`after` 快照与 `epoch`
- `templates/`、`static/`：核对页；`static/diff.js` 是无 DOM 依赖的对比/班次
  纯逻辑模块，`static/app.js` 只负责把它接到页面
- `tests/`：算法对照、持久化/回滚、HTTP、并发、规模（SQL 语句数不随 N 线性增长）、
  交错补改前后快照（`test_diff_api.py`、`test_interleave.py`）；前端纯逻辑用
  `node --test tests/js/diff.test.js` 运行
